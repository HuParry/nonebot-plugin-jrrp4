# 今日人品算法：通俗原理说明

这个算法可以理解为一次“每天固定的抽签”：签上写着 0～100 分，好日子会让高分签更容易被抽中；每个人当天抽到的签会被保存，重复查询不会重新抽签。

它要同时做到两件事：**同一个人当天的结果不变，以及好日子获得高分的概率更大。**

这里的分数用于娱乐。算法可以严谨地控制概率，但不能证明一个人的现实运气，也不能证明黄历对现实事件的影响。

## 1. 平常日子：中间分数常见，极端分数少见

先想象一个装着许多签的盒子，每张签上写一个分数。有些分数的签多，有些分数的签少。

普通日子的规则是：50 分附近的签较多，0 分和 100 分的签较少，低分和高分的安排关于 50 分对称。

每个分数的“签数”用下面的权重表示：

```text
基础权重 = (分数 + 1) × (101 - 分数)
```

例如：

| 分数 | 基础权重 |
| ---: | ---: |
| 0 | 101 |
| 25 | 1976 |
| 50 | 2601 |
| 75 | 1976 |
| 100 | 101 |

权重越大，越容易抽到；把一个分数的权重除以全部分数权重之和，就得到它的抽中概率。**权重不是最终分数，也不是百分比。**

这样安排后，普通日期的平均分为 50，但任何一个具体账号仍可能得到 0～100 中的任意整数分数。

## 2. 好日子：给高分签更多机会

算法根据当天的日期，计算一个参数 `b`：

| 当天满足的条件 | b 增加多少 |
| --- | ---: |
| 黄道日 | 1 |
| 中国大陆法定放假日 | 2 |
| 黄历吉神中包含“天赦” | 3 |

条件可以叠加。例如，某一天既是黄道日，又是法定放假日，就得到 `b = 3`；三项全部满足时，`b = 6`。

这里采用的日期口径是：

- 黄道日和天赦日按 `lunar-python` 的黄历数据判断。
- 法定放假按 `chinesecalendar` 的放假安排判断；普通周末、调休上班日不额外获得节假日权重。
- 尚未收录放假安排的年份只使用黄历权重，并提醒维护者更新节假日数据。
- 黄历流派可能不同，“天赦日”也不意味着所有活动都适合进行。

得到 `b` 后，每个分数的权重调整为：

```text
当天权重 = 基础权重 × (1 + b / 100)^分数
```

其中 `^` 表示乘方。例如，`1.01^75` 表示 75 个 `1.01` 相乘。

当 `b > 0` 时，这个乘数会随着分数升高而增大。于是高分签相对于低分签的数量增加，高分就更容易抽到了。

**b 调整的是概率。** 例如 `b = 3` 时，仍然只抽取一次结果，并不会在抽到的分数上直接加 3。

### 概率会怎样变化？

没有配置高、低名单时，理论概率如下，显示值已四舍五入：

| 日期条件 | 获得至少 75 分 | 获得至少 85 分 |
| --- | ---: | ---: |
| 普通日期，b = 0 | 16.74% | 7.00% |
| 仅黄道日，b = 1 | 22.88% | 10.18% |
| 仅法定放假，b = 2 | 29.80% | 14.06% |
| 仅天赦日，b = 3 | 37.13% | 18.53% |
| 三项全部叠加，b = 6 | 58.27% | 33.76% |

可以把 16.74% 理解为：如果有很多账号按这个分布抽签，平均大约每 100 个账号中有 17 个得到至少 75 分。具体某一天的实际人数会有波动，也不能保证一个人查 100 天恰好有 17 天达到 75 分。

这个公式有一个经过数学推导和测试验证的性质：在相同分数范围内，`b` 增大时，“达到或超过某个分数”的概率都会增大，例如 60 分、75 分、90 分和 100 分。

所有允许分数的权重仍然大于零。因此，好日子可能抽到低分，普通日子也可能抽到满分；好日子当天的分数也可能低于前一天。

## 3. 为什么既能随机，又能保证当天不变？

普通的随机抽签每次都可能得到不同结果。为了避免重复查询刷新分数，插件使用“可以重现的伪随机抽签”。

首次初始化时，插件从操作系统的安全随机源生成一份秘密种子，并将它保存下来。可以把种子理解为这台机器人的“抽签钥匙”。

随后，用这份种子处理下面的信息：

```text
算法版本 + 完整日期 + 被查询者的 QQ 号
```

处理方法叫作 `HMAC-SHA256`。它会生成看起来随机、但相同输入可以重现的数字，用来确定抽到哪张签。

- 同一账号、同一天、同一份种子：抽样过程可以重现。
- 换一个日期或账号：使用不同输入生成新的抽样数字。
- 群号和查询次数不参与计算：跨群查询或多次查询不会刷新分数。

这是密码学方法生成的伪随机数，并非每天采集一次物理随机数。新一天使用不同的抽样输入，但两天仍可能恰好得到同一个整数分数。

## 4. 怎么避免抽签时的计算偏差？

代码实际使用精确的整数权重计算，不需要真的制作一个装签的盒子，也不依赖浮点数近似概率。

抽签过程可以理解为：

1. 按分数从小到大排列所有签，并给每张签编号。
2. 生成一个随机编号。
3. 找到该编号对应的分数。

如果生成的编号超出盒子中的签数，就丢弃这个编号，生成新的编号。这样做叫“拒绝采样”。

它能避免一种常见偏差：直接用取余把越界编号折回范围，会让某些编号有更多机会被选中。拒绝采样保持编号抽取的均匀性，再由各分数的签数决定其概率。

## 5. 为什么重启后分数也不会变？

插件在 `luck.sqlite3` 数据库中保存三类信息：

| 保存的信息             | 用途                       |
|------------------------|----------------------------|
| 秘密种子               | 让抽样过程可以重现         |
| 当天日期权重           | 固定当天使用的历法规则     |
| 每个账号当天的最终分数 | 重复查询时直接返回已有结果 |

当天第一次有人查询时，插件保存当天的日期权重。每个账号第一次查询时生成并保存分数，之后优先读取这个分数。

因此，重启机器人、当天更新历法依赖或修改名单，都不会改变已经生成的当天结果。修改名单只影响尚未生成结果的账号和未来日期。

数据库事务也会处理同时到来的查询，保证同一账号当天不会因为并发请求生成两个不同结果。

迁移机器人时需要保留数据库；删除数据库或丢失种子后，无法保证恢复原来的结果。不同机器人默认有不同种子，因此同一账号在不同机器人上可能得到不同分数。

日期统一采用北京时间，也就是 `Asia/Shanghai` 时区，零时换日；同一天内不因为查询时间不同而改变黄历权重。

## 6. 高、低人品名单怎么参与？

名单会先限定允许抽到的分数范围：

| 名单       | 允许范围 |
|------------|----------|
| 不在名单中 | 0～100   |
| 高人品名单 | 75～100  |
| 低人品名单 | 0～40    |

例如，低名单相当于只保留写着 0～40 分的签，然后在这些签中抽取。范围内部仍使用同一套日期加权方法，因此好日子更容易抽到该范围中的较高分。

同时出现在两个名单中时，高名单优先。低名单不会出现直接命中 100 分的例外。

名单属于人为指定的偏好；默认名单为空时，所有账号在同一天使用相同的概率分布。群聊等级配置只决定能否查询，不影响人品分数的计算。

## 7. 如何理解算法的“科学性”？

可以验证的部分包括：概率分布明确、抽样避免取模偏差、每日结果稳定，以及好日子对高分概率的提升。

基础分布的形状和黄道日、放假日、天赦日的增量，是为了实现所需体验而选择的规则，没有经过现实运气数据的拟合。分数越高，代表在本娱乐模型中抽到的结果越有利。
